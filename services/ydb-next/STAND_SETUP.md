# Изолированный стенд Медси Бот — YDB

Документ только для ветки `feature/ydb-unified-cutover`. Пока эта ветка
на тестировании, `timeweb-next`, рабочий Timeweb, Apps Script, Cloudflare и
действующий домен не меняются.

## Технический запуск

Рабочие исходники фронтенда лежат в том же репозитории. На отдельном
тестовом стенде GitHub branch `feature/ydb-unified-cutover`:

1. Установить Node.js 22.
2. Для сборки использовать `npm ci`. В этой ветке корневой `postinstall`
   устанавливает зависимости `services/ydb-next`.
3. Стартовая команда: `npm start`, root `package.json` в feature-ветке
   специально запускает **только** изолированный YDB stand.
4. Применить схему *только на пустой изолированной YDB*:
   `MEDSI_NEXT_APPLY_TEST_SCHEMA=YES npm --prefix services/ydb-next run schema:test`
   с указанными ниже защищёнными переменными окружения.
5. Проверить `GET /__health`; затем на вымышленных записях проверить
   полный родительский и воспитательский flow.

## Переменные окружения — в секретах стенда, не в репозитории

| Имя | Значение |
| --- | --- |
| `MEDSI_NEXT_STAND` | `1` — обязательный флаг изолированного стенда |
| `MEDSI_NEXT_YDB_ENABLED` | `1` — разрешить реальное соединение с YDB |
| `YDB_CONNECTION_STRING` | Полный `grpcs://...` endpoint с параметром `database=` из консоли YDB |
| `YDB_SERVICE_ACCOUNT_JSON` | **Весь** JSON авторизованного ключа сервисного аккаунта |
| `NEXT_SESSION_SECRET` | Новый случайный секрет от 32 символов (не публиковать) |
| `NEXT_TUTOR_LOGIN` | Отдельный логин воспитателя стенда |
| `NEXT_TUTOR_PASSWORD` | Случайный пароль воспитателя стенда |
| `NEXT_TUTOR_VERSION` | `ydb-stand-v1` |
| `PARENT_PASSKEY_RP_ID` | Relying party ID текущего **HTTPS-домена** стенда |
| `PARENT_PASSKEY_ORIGIN` | `https://` + этот же домен |
| `VAPID_PUBLIC_KEY` | Открытый VAPID-ключ push |
| `VAPID_PRIVATE_KEY` | Секретный VAPID-ключ push |
| `VAPID_SUBJECT` | Контактный mailto: для push |
| `PORT` | Порт из среды Timeweb, если предоставлен |

Не копировать авторизованный ключ в GitHub, в чат, в публичные логи или
в браузерную консоль. Открытый endpoint сам по себе не предоставляет доступ.

## Важные ограничения текущего стенда

- Схема применима только к **пустой тестовой** YDB. Стенду нужны вымышленные
  дети, активные госпитализации, тестовые родители и ключи.
- Media upload/view намеренно закрыты до появления проверки владения
  вложением и полномочий на S3. Нельзя оставлять медицинские файлы с
  незащищённым публичным URL.
- Реальную историю из Cloudflare/Sheets/KV ещё нельзя автоматически
  перенести — нужны отдельные export/import, HMAC сверка и разрешённая среда.
- Родительская регистрация требует подтверждения воспитателем и привязки
  к активной госпитализации, а восстановление доступа — подтверждения
  воспитателем. В тестовом контуре действующие аккаунты отсутствуют до импорта.
- Стенд не отправляет запросы Google Apps Script или Cloudflare. Старые
  `tw1.` сессии не предназначены для входа на новый технический домен.
- Старые passkeys привязаны к домену `медси-бот.рф`. На техническом
  домене тестируйте отдельно созданные ключи; финальный перенос должен
  сохранить действующие credentials и RP ID рабочего домена.
- **Запрещено** назначать `медси-бот.рф` на стенд или объединять ветку
  с `timeweb-next` до E2E и полного аудита.
- Ветка feature меняет root `npm start` намеренно: при будущем
  объединении с production это решение должно быть включено в отдельный
  одобренный cutover с восстановлением обычной production-сборки.

## Приёмочный минимум

Отчёты (три вида + распределение + два родителя + повторное поступление),
чаты, ручная правка словаря имён, Face ID на iOS, уведомления, история,
регистрация и восстановление, удаление родителя и S3, все действия воспитателя,
сверка импортов, доступность при отключении YDB, восстановление резервной копии.
Каждый пункт подтверждается реальным интеграционным тестом, а не только fake-YDB.

# Панель врачей Медси Бота

## Timeweb

- `DOCTORS_ENABLED=1` включает `/doctors`. Удаление флага отключает страницу, API и фоновую синхронизацию. Записи в PostgreSQL сохраняются.
- Вход по умолчанию использует `NEXT_TUTOR_LOGIN` и `NEXT_TUTOR_PASSWORD`. Для смены учётных данных врачей задайте одновременно `DOCTORS_LOGIN` и `DOCTORS_PASSWORD`. Врачебная сессия использует собственную cookie.
- `DOCTORS_EXCLUDED_PHONES` принимает список тестовых телефонов через запятую. Этот фильтр применяется при чтении телефонной книги бота.
- `DOCTORS_GREENWOOD_SHEET_ID` включает чтение реестра «Стационар Гринвуд». Нужен ID между `/d/` и `/edit` и доступ на чтение по ссылке. Бот делает только анонимный запрос к вкладке «5 этаж» за ФИО и датой поступления. Если подтверждён столбец выписки, задайте `DOCTORS_GREENWOOD_DISCHARGE_COLUMN` (одна буква A–Z, кроме C и G); тогда читается и эта дата как резервная после правки врача и плана. По умолчанию столбец выключен. Строки с пустой или нераспознанной датой поступления видны, но для них отключены медицинские даты, автоматическое сопоставление и редактирование до заполнения реестра. Дата поступления из таблицы служит резервным источником на карточке, пока не найден план текущего пребывания; она также помогает различать повторные госпитализации. После успешного обновления раздел показывает только детей, которые сейчас есть в таблице. Открытый список проверяется каждые 30 секунд. При временном отказе Google панель показывает последний полученный список, если он есть в памяти процесса. Изменения при недоступном реестре отклоняются.
- Без `DOCTORS_GREENWOOD_SHEET_ID` проверять интерфейс можно со списком из PostgreSQL. Телефоны и имена родителей доступны в карточке «Телефоны». В режиме Google контакты на карточках пациентов требуют подтверждённого соответствия между строкой и профилем. В текущей вкладке общего идентификатора нет. Для ручного подтверждения оператором доступен `DOCTORS_VERIFIED_CONTACT_LINKS`: JSON-массив пар `[идентификатор строки текущего пребывания из /doctors/api/patients, идентификатор ребёнка из /doctors/api/phones]`. Оба идентификатора непрозрачны и доступны только после врачебного входа. Оператор должен отдельно подтвердить личность по надёжному источнику; совпадение имени само по себе не является подтверждением. Связи действуют только для конкретной строки и даты поступления, требуют привязанного `child_id` и совпадения имени/фамилии, не переносятся на новую госпитализацию. Дубли или невалидная конфигурация отключают все такие связи. Не публикуйте значения в Git или логах.
- `DOCTORS_DISK_ROOT` задаёт канонический путь к папке пациентов, например `disk:/Документы/Пациенты`, без конечного `/` и без `.`/`..` в пути. Если папки пациентов лежат непосредственно в корне Диска, укажите `disk:/` (это допустимое исключение для конечного `/`). Синхронизатор открывает только папки, соответствующие актуальным пациентам; выделенная тестовая папка исключена при сканировании корня. Корень разрешён для чтения и отдельно согласованной рабочей записи, но не для тестовой записи. `DOCTORS_DISK_TOKEN` берётся из секретов Timeweb. `DOCTORS_DISK_INTERVAL_MS` по умолчанию составляет 300000 мс.
- `DOCTORS_DISK_TEST_WRITE=1` разрешает запись исключительно в выделенную папку `disk:/medsi-doctors-test`: обе переменные `DOCTORS_DISK_ROOT` и `DOCTORS_DISK_WRITE_TEST_ROOT` должны содержать ровно этот путь. Для защиты от ошибочной конфигурации ограничение действует также внутри HTTP-клиента загрузки. Создавайте её только на отдельной тестовой учётной записи, с синтетическими копиями, не с оригиналами. Перед включением настройте закрытый S3 и срок хранения объектов с префиксом `doctor-plan-backups/`. В рабочей среде с оригиналами оставьте тестовые параметры пустыми.

## Рабочая запись (отдельное включение)

По умолчанию рабочая запись отключена даже при OAuth с правом write. После проверки чтения, закрытого S3 и согласования ответственного сотрудника задаются одновременно:

- `DOCTORS_DISK_WRITE_ENABLED=1` (тестовый флаг должен отсутствовать).
- `DOCTORS_DISK_CONCURRENT_EDIT_ACK=1` — подтверждение ограничения API: Excel нельзя одновременно редактировать вручную во время записи из бота. Полностью устранить гонку без атомарной операции Яндекса невозможно.
- `DOCTORS_DISK_WRITE_EPOCH` — уникальная строка 12–128 символов A–Z/a–z/0–9/_/-. Сменить при повторном включении после отключения. Операции из другого режима, корня, OAuth-токена, реестра или поколения не исполняются без повторного подтверждения врача.
- `DOCTORS_GREENWOOD_SHEET_ID`, `DOCTORS_DISK_TOKEN`, `DOCTORS_DISK_ROOT` и настроенный закрытый S3 обязательны.

Для сопоставления папок и ФИО внутри Excel используется существующий справочник вариантов имён Медси Бота. Фамилия должна совпадать, допускается перестановка первых двух слов и стандартные суффиксы возраста. Неоднозначные варианты, совпадения нескольких пациентов/папок и противоречащие отчества не сопоставляются автоматически. При изменении справочника или состава реестра прежнее подтверждение принадлежности планов перепроверяется. Контакты по-прежнему требуют отдельно подтверждённой связи.

Рабочая запись допускает только XLSX-планы непосредственно внутри проверенной папки актуального пациента, с совпадающей датой поступления. Для восстановления в закрытом S3 перед загрузкой хранятся оригинальный XLSX и JSON-манифест с путём, ключом копии, SHA-256 оригинала и записываемой версии. Манифест содержит конфиденциальные данные; не выводить его в логах. После подтверждённой записи всех планов и фиксации статуса synced в PostgreSQL временные объекты этой операции удаляются. Неудачная или частичная запись сохраняет копии для восстановления; сбой очистки повторяется в следующих циклах того же рабочего поколения. Ранее созданные объекты без записи в журнале очистки автоматически не удаляются. При включённом версионировании S3 удаление текущего объекта не удаляет его исторические версии; политика хранения настраивается отдельно. Применять ту же политику доступа и хранения, что и к копиям. Восстановление только после отключения записи и проверки текущего хеша: если он отличается от replacementSha256, автоматическое восстановление запрещено. Оператор восстанавливает копию вручную после проверки, чтобы не потерять последующие изменения. Смена режима не удаляет данные. Удаление флага записи останавливает загрузки после перезапуска приложения.

## Подключение Яндекс OAuth

1. Создайте OAuth-приложение в [Яндекс OAuth](https://oauth.yandex.ru/). Выберите право чтения Яндекс.Диска (`cloud_api:disk.read`). Для отдельной учётной записи с тестовыми копиями и проверкой записи добавьте право `cloud_api:disk.write`.
2. Авторизуйтесь как владелец нужных папок, пройдите согласование и получите токен через [официальный OAuth-процесс](https://yandex.com/dev/disk/rest/).
3. Запишите токен в переменную `DOCTORS_DISK_TOKEN` в настройках приложения Timeweb. Укажите путь, заданный в `DOCTORS_DISK_ROOT`. Пароль от Яндекс-аккаунта для бота не требуется.

## Диагностика доступа без записи

На согласованном стенде с уже установленными зависимостями и секретами в окружении выполните:

```sh
node scripts/probe-doctors-disk.mjs
```

Команда проверяет OAuth и путь к папке, не обращается к PostgreSQL или S3 и ничего не меняет на Диске. В выводе только статус и число непосредственных дочерних папок. Она не скачивает документы. Не вставляйте токен в команду, историю shell, Git или чат.

После создания отдельной учётной записи и папки `disk:/medsi-doctors-test` с синтетическим XLSX-планом (поля даты и вымышленного ФИО должны быть заполнены) можно дополнительно проверить получение и распознавание одного файла:

```sh
DOCTORS_DISK_PROBE_SAMPLE=1 node scripts/probe-doctors-disk.mjs
```

Этот режим разрешён только в фиксированной тестовой папке. Он проверяет контрольную сумму и чтение шаблона, но не загружает изменённый файл. Успех диагностики не подтверждает право записи или защиту от внешнего редактирования. Для проверки записи нужен отдельный согласованный тестовый стенд.

После входа в `/doctors` можно открыть `/doctors/api/diagnostics` в том же браузере. Ответ доступен только с врачебной cookie, не кешируется и показывает режим записи, наличие конфигурации, время последнего цикла, ошибки и агрегированные числа пациентов/папок/планов. Имена, пути, даты пребывания, токены и содержимое файлов не выдаются. `lastComplete` означает завершение цикла без исключений, а не подтверждение всех сопоставлений; отдельно проверяйте `counters`.

Поле `issues` диагностики содержит только фиксированные коды и числа: проблемы реестра/корня, отсутствие или неоднозначность папки, ошибки списка файлов, скачивания, хеша, распознавания полей XLSX и несовпадение даты поступления. `matched` учитывает найденную папку до чтения файлов. При частичном сбое годный план может быть прочитан, но запись в папку блокируется. Если ни один текущий план не прочитан из-за временной ошибки, предыдущий снимок сохраняется. Переадресации скачивания допускаются только по HTTPS между проверенными доменами Яндекса, без OAuth-заголовка.

## Изменение выписки

Правка врача сначала фиксируется в PostgreSQL. Синхронизатор проверяет принадлежность документов, выбирает планы текущего пребывания, проверяет даты во всех файлах и сохраняет копии перед загрузкой. После каждой загрузки скачивает файл и сверяет хеш. Если процесс прерывается после загрузки части файлов, повторная проверка пропускает планы с уже установленной датой. В интерфейсе отображается одна дата. До синхронизации приоритет у сохранённой правки врача. Без ожидающей правки используется итоговый план текущей госпитализации, затем самый свежий доступный план. При равной свежести сравнивается дата в названии файла, затем выбирается более поздняя дата выписки. При записи правка врача применяется ко всем проверенным планам текущего пребывания с сохранением резервных копий. Неоднозначность принадлежности документа или несовпадение версии при загрузке блокируют запись или откладывают её до повторной проверки. Независимая правка даты (отличная от исходной и желаемой) блокирует всю операцию до записи любых очередных файлов. Конфликт не повторяется автоматически; после проверки документа врач должен явно подтвердить выбранную дату и заново сохранить её относительно свежего снимка. Для реестра дата начала в плане должна совпасть с датой поступления в строке: пересечение диапазонов недостаточно, поскольку оно может принадлежать старому пребыванию. Если даты расходятся, оператор должен сверить источники; без даты пребывания запись в Excel отключена. Ошибка одной папки не останавливает обработку остальных пациентов. Перед каждой загрузкой повторно проверяется актуальный состав реестра; скачанные байты сверяются с хешем SHA-256 (или MD5, если API не отдаёт SHA-256). Пути проверяются как прямые потомки ожидаемой папки. После записи проверяется, что ни один исходно выбранный план не исчез из результата сканирования. Новый план без ранее известной версии допускает запись только при пустой выписке либо уже совпадающей дате.

Яндекс.Диск не предоставляет проверенную атомарную операцию сравнения версии при перезаписи через ссылку загрузки. Между заключительной проверкой и загрузкой остаётся окно для внешней правки. Рабочая запись требует отдельных флагов и организационного исключения одновременного редактирования.

## Проверка

`npm run verify` и `npm run verify:postgres-next` проверяют приложение. Для дополнительной проверки очереди на локальном чистом PostgreSQL передайте его порт в `MEDSI_DOCTORS_TEST_PG_PORT` и запустите `node --test services/postgres-next/app-test/doctors-panel.test.mjs`. Тест пользуется синтетическими документами и имитирует Яндекс.Диск и S3. CI отдельно запускает этот тест на одноразовой базе PostgreSQL 18, чтобы интеграционный сценарий не был пропущен.

## Порядок безопасного выпуска

1. Проверить обе команды CI на актуальном HEAD и отдельно выполнить PostgreSQL-тест с `MEDSI_DOCTORS_TEST_PG_PORT` на чистой локальной БД. Проверить сохранность нецелевых частей двух обезличенных XLSX.
2. В отдельном стенде настроить `DOCTORS_ENABLED=1`, исключения телефонов и при необходимости реестр. Не использовать production-секреты и медицинские данные в CI. Проверить список и роли.
3. С согласия оператора использовать отдельную учётную запись Диска и папку синтетических копий; настроить read/write-токен, `DOCTORS_DISK_ROOT`, `DOCTORS_DISK_WRITE_TEST_ROOT` (оба пути строго `disk:/medsi-doctors-test`), закрытый S3 и `DOCTORS_DISK_TEST_WRITE=1`. Проверить несколько планов, резервные копии, повтор после частичного сбоя и остановку на конфликте.
4. После отдельного согласования включить чтение рабочей папки с read-only токеном и отключёнными тестовыми флагами. Проверить актуальность и однозначность соответствий, не редактируя оригиналы. Ссылка Google с доступом всем обладателям ссылки требует согласования ответственного за конфиденциальность; не размещать её в Git.
5. Рабочий режим реализован, но по умолчанию выключен. Не обходить тестовый ограничитель. Перед включением проверить закрытость резервного хранилища, восстановление копии и согласовать порядок исключения одновременного редактирования Excel. Затем применить отдельные флаги рабочего режима; старые ожидающие операции потребуют повторного подтверждения.
6. После согласования релиза проверить smoke/cutover safety, включить согласованные флаги и контролировать обезличенные ошибки. Для отключения убрать `DOCTORS_ENABLED`; существующие панели и сохранённые данные остаются. Не менять DNS, production DB/S3 или секреты без разрешения.

- Существующий Timeweb App Platform и тот же HTTPS-домен для сайта, Node.js API, отчётов, чатов, авторизации, уведомлений и периодических задач.

## PostgreSQL-код и безопасный запуск

- `services/postgres-next/sql/001_initial.sql`: 27 таблиц и индексы, не выполняется автоматически при запуске сайта.
- `services/postgres-next/src/connection.mjs`: параметризованные SQL-запросы, преобразование PostgreSQL UPSERT, транзакции, pool, TLS с проверкой CA, корректный rollback.
- `services/postgres-next/src/schema-cli.mjs`: создаёт структуру **только в пустой БД** при явном подтверждении; на каждом деплое не запускается.
- `server.js`: при `MEDSI_NEXT_STAND=1` и `MEDSI_NEXT_PG_ENABLED=1` запускает NEXT с PostgreSQL. Если эти флаги отсутствуют — остаётся старый Timeweb gateway. В текущей реализации PostgreSQL NEXT **изолирован** и не считается разрешённым production-backend.
- `.github/workflows/verify-postgres-next.yml`: Node.js 22 + временная PostgreSQL 18, регрессия NEXT и старого gateway, тесты на фиктивных данных. Если GitHub Actions красный — merge и cutover запрещены.

## Параметры подключения Timeweb

Нужны в **секретах приложения** (не в GitHub, чате, истории терминала или конфигурационном файле):

| Переменная | Назначение |
| --- | --- |
| `PGHOST` | Точный hostname PostgreSQL, выданный Timeweb (желательно DNS-имя, проверяемое сертификатом) |
| `PGPORT` | TCP-порт из панели (обычно 5432, но брать реальный) |
| `PGDATABASE` | Название созданной базы |
| `PGUSER` | Пользователь с минимальными нужными правами |
| `PGPASSWORD` | Пароль этого пользователя |
| `PG_SSL_CA_PEM` / `PG_SSL_CA_B64` | Доверенный CA сертификат сервера; TLS всегда с проверкой сертификата |
| `MIGRATION_AUDIT_HMAC_KEY` | Секретный ключ для подписи полных capture-манифестов; 32+ байта, только защищённая среда миграции |
| `MEDSI_NEXT_PG_ENABLED` | В NEXT включить PostgreSQL (`1`); **не включать в production до cutover** |
| `MEDSI_NEXT_STAND` | Только изолированный режим для подготовленного NEXT-кода (`1`) |
| `NEXT_SESSION_SECRET` | Сильный отдельный секрет сессий, не меньше 32 символов |
| `NEXT_TUTOR_LOGIN/PASSWORD/VERSION` | Согласованные параметры входа воспитателя |
| `PARENT_PASSKEY_RP_ID` / `PARENT_PASSKEY_ORIGIN` | Действующий RP ID и точный HTTPS-origin, если сохраняем passkeys |
| `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` / `VAPID_SUBJECT` | Прежняя пара Web Push и адрес отправителя — для сохранения подписок |
| `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY` | Прежний приватный S3 для медиа; не создавать новый бакет |

Переменные текущего gateway при выключенном NEXT: `SESSION_SECRET`, `APP_SCRIPT_URL`, `CHAT_UPSTREAM`, `UPLOAD_UPSTREAM`, `PUSH_UPSTREAM`, `MIGRATION_SHARED_SECRET`, `REPORTS_SYNC_SECRET`; S3 использует общие `S3_BUCKET`/`S3_ACCESS_KEY`/`S3_SECRET_KEY` и необязательные `S3_ENDPOINT`/`S3_REGION` (Timeweb defaults). Не удалять и не менять их при подготовке NEXT.

Дополнительные переменные NEXT, сверенные с кодом: `PORT` (предоставляет платформа), `MAX_UPLOAD_BYTES` (необязательный лимит), `MEDSI_NEXT_DELETION_ENABLED`, `MEDSI_NEXT_LEGACY_AUTH_ENABLED`, `NEXT_LEGACY_D1_SESSION_SECRET`, `NEXT_LEGACY_TUTOR_LOGIN`, `NEXT_LEGACY_TUTOR_PASSWORD`, `NEXT_LEGACY_TUTOR_VERSION`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`. Legacy-auth values применяются только после отдельной сверки сессий и подтверждения необходимости их чтения; не активировать заранее.

`PG_SCHEMA_CONFIRM`, `MEDSI_NEXT_MIGRATION_PREFLIGHT`, `MEDSI_NEXT_SEED_DEMO`, `CI`, `NODE_ENV`, `PG_TEST_INSECURE_LOCAL` — только разовые/CI-переменные; их нельзя сохранять в production-переменных. `DATABASE_URL`, `DATABASE_SSL`, `DATABASE_POOL_MAX` относятся к старому health-check-слою и не являются конфигурацией NEXT; не направлять их на купленную БД. Значения переменных в репозиторий не копировать.

### Текущий статус подготовки (5 ноября 2026)

Медси Бот 2.0 — полноценное приложение, которое готовится стать основным. Оно создано отдельным ресурсом Timeweb и подключено к существующей PostgreSQL через приватную сеть; тариф минимальный, с почасовым списанием. Защищённые переменные приложения и настройки входа сохранены, пароль БД задан владельцем непосредственно в Timeweb. В базе установлена пустая схема из 27 таблиц и 5 индексов; подключение и схема проверены. Домены, production-ветка, данные пациентов, Apps Script, Cloudflare и push действующей системы не переключались.

Полный перенос реальных рабочих данных пока не выполнялся. Разрешение пользователя на их загрузку относится к этапу переноса после готовности источников и write-freeze. Зелёные тесты на синтетических данных не означают, что реальные данные уже захвачены или сверены.

Реальные данные пока не захватывались.
2. Сверить текущие и исторические отчёты между Sheets, свойствами Apps Script и D1, не угадывая даты публикации или принадлежность к госпитализации. Неоднозначные записи требуют ручного разрешения до импорта.
3. Снять реальную карту объектов S3 и сверить их с сообщениями. Существующие объекты остаются на месте; новые копии не создаются для уже существующих ключей. Реальная проверка объектов пока не выполнена.

Ненулевые очереди требуют отдельной проверенной политики: завершить, безопасно воспроизвести или импортировать; без такой политики перенос блокируется.

6. До переключения доказать write-freeze всех независимых старых писателей и подготовить обратную дельту после открытия записи в 2.0. Сейчас это план и код сверки, а не установленный барьер действующих сервисов.
7. Перед окном переноса перепроверить прежний RP ID/origin, VAPID-пару, сессии и защищённые секреты. Сверить релизный механизм Timeweb 1.0, чтобы обновление 2.0 не заменило версию для отката.

## Проверка интерфейса и восстановления

- На техническом домене подтверждён вход воспитателя. Разделы исходных отчётов и чатов корректно показали пустое состояние. Проверены создание и удаление одного вымышленного варианта имени. Доставка сообщений и вложений на развёрнутом приложении этим прогоном не подтверждена.
- В CI PostgreSQL 18 восстановлена из логического бэкапа. Контрольные суммы всех 25 SQL-потоков совпали. Эта репетиция не заменяет резервную копию и проверку восстановления управляемой базы Timeweb и не проверяет S3.


### Проверка одного полного ночного переноса

Запускать сравнение после импорта, пока запись закрыта с обеих сторон. Передать три подписанных манифеста одного окна: исходный снимок, PostgreSQL вместе с проверенным S3 и свежий снимок источника. Третий манифест строится повторным чтением источника, а не копированием первого файла.

```sh
MEDSI_NEXT_MIGRATION_PREFLIGHT=YES node services/postgres-next/app/migration-gate.mjs   source-before.json destination.json source-after.json
```

Ключ HMAC подаётся в защищённом окружении. `SOURCE_CHANGED_OR_INCOMPLETE` блокирует переключение: проверить остановку старых писателей и повторить сверку в новом согласованном окне. Штатный сценарий не предусматривает предварительный перенос и последующий импорт дельты. Обратная дельта после открытия записи в 2.0 остаётся отдельной частью отката.

### Что остановить в ночном окне

По исходному коду есть несколько независимых путей записи. Перед выгрузкой нужно сверить фактически включённые маршруты и триггеры, сохранить их конфигурацию для отката и подтвердить остановку каждого пути:

- Timeweb 1.0 и прямые клиентские адреса Cloudflare: чат, загрузка вложений, регистрация, изменение профиля и отметки прочтения. Простая смена домена не перекрывает ранее выданные адреса Worker.
- Chat Worker: расписание сохраняет историю отчётов и обрабатывает очереди отчётов и удаления. Дождаться завершения активных запусков; отдельно закрыть пишущие административные маршруты.
- Apps Script и Sheets: ручное редактирование исходников и реестра, веб-вызовы, триггеры изменения, плановое обслуживание, повторы синхронизации и очередь очистки S3.
- Push Worker: изменения подписок и отправка уведомлений. Проверить остановку без удаления действующих подписок.
- S3: проверить остановку старых загрузок и удалений. Существующие объекты в том же бакете сохраняют ключи; в PostgreSQL переносятся ссылки и принадлежность чатам.

Установка такого ограничения для действующей системы ещё не проверена. Сверка трёх манифестов обнаруживает дрейф между снимками, но не заменяет остановку писателей.

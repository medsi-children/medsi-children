# МЕДСИ БОТ — переход на Timeweb + Yandex YDB (параллельная разработка)

**Статус: подготовка, без переключения пользователей.**

## Жёсткие ограничения

- Единственная рабочая ветка: `timeweb-next`. Вся разработка здесь — только `feature/ydb-unified-cutover`.
- Нельзя переключать существующие URL, менять Timeweb production variables, публиковать Apps Script/Cloudflare или отключать синхронизацию контактов в *старой* системе до явного подтверждения финального перехода.
- Текущий сайт, Google Apps Script, Cloudflare D1/Workers/KV и Google Contacts продолжают работать как раньше.
- **На новом сервере Google Contacts не подключаем и не синхронизируем**. Данные родителей и детей в People API из новой системы не отправляются; после cutover старый hourly trigger нужно отключить явно.
- Работаем с вымышленными данными, пока база, шифрование, роль клиники, полномочия и правовые основания не согласованы. Реальные экспорты — только в одобренной среде, без GitHub, чата, dump-файлов CI и персональных данных в логах.
- Продакшен-схема и тестовая схема должны быть разными, с разными ключами и учётными записями. Никакой двойной записи из браузера во время подготовки.

## Цель

```
Родители / воспитатели / психологи
    https://медси-бот.рф (тот же origin)
        |
        v
Timeweb Node.js: API, отчёты, чат, регистрация, passkeys, Web Push,
                 планировщик, новые вкладки воспитателей
        |                           |
        v                           v
Yandex YDB Serverless (RU)     Timeweb S3 (RU)
все структурированные данные   приватные файлы/медиа
```

Существующие REST-URL `/lab/*`, `/push/*`, `/__session/apps-script` на время миграции обслуживаются старым сервером. Новая реализация изолирована и не монтируется в production до единого cutover.

## Соответствие старых данных новым

| Источник | Новая схема | Особенности |
|---|---|---|
| `REPORTS` из Sheets и `chat_profiles` D1 | `children`, `admissions`, `parent_profiles` | Сопоставить родителей, поколение профиля и идентификатор госпитализации |
| `NAME_VARIANTS` | `name_variants` | Первый столбец — preferred raw heading; не переименовывать зарегистрированное имя |
| `MORNING/EVENING/PSYCHOLOGY` | `raw_reports` | Оригинал и каноническая версия, история публикаций |
| Отчёты в `REPORTS`, `report_current` D1 | `parent_current_reports` | Разделение по номеру взрослого; `admission_id`, `revision`, `read_version` |
| `report_snapshots` D1 | `parent_report_history` | Даты, поколения, 45-дневный срок текущей истории (проверить политику хранения) |
| `chat_messages`, `chat_pins` D1 | аналогичные YDB таблицы | Сохранить `message_key`, replies, реакции, статусы и прочитанность |
| `parent_auth_profiles`, `parent_passkeys`, sessions | таблицы авторизации YDB | Перенести существующие публичные ключи, не требовать повторной привязки без необходимости |
| Cloudflare push KV | `push_subscriptions` | VAPID-ключи сохранить в secrets Timeweb, не в БД/GitHub |
| Timeweb S3 | Timeweb S3 | Медиа не перекопировать без нужды; сверить все ссылки и права доступа |
| Google `MEDSI_CONTACT_SYNC` + People API | **нет нового обработчика** | Sync Contacts прекращает работу при cutover; отдельно отключить Google trigger |

## Алгоритм отчётов

1. Воспитатель отправляет общий сырой отчёт с `submissionId`. Node.js выполняет ту же проверку, коррекцию и сверку с активным составом детей, что и Apps Script.
2. Новый план распределения формируется целиком и проверяется **до сохранения**. Непривязанные, дублированные и неоднозначные заголовки блокируют публикацию. Обязательна защита от повторной госпитализации, одинаковых ФИО и перемены телефонного номера.
3. Одной транзакцией YDB записываются исходный и исправленный текст, `parent_current_reports`, история и версии. Контроль `submissionId` исключает повторы, `submitted_at` не допускает публикации более старого отчёта.
4. Push-уведомления добавляются в outbox **в той же транзакции**; отправляются отдельным воркером после commit. Содержимое push без диагнозов/отчётных текстов.
5. Сырые отчёты и распределённые записи доступны воспитателю в новой вкладке. `NAME_VARIANTS` редактируется с проверками и журналом изменений; изменение вариантов имени не должно само по себе переприсвоить отчёт другой семье.
6. Храним нужную историю согласно утверждённым клиникой срокам; временные очереди чистятся отдельно, **без потерь и без хранения в зарубежных системах**.

## Полный переход за одно переключение

1. Собрать все серверные модули и UI в этой ветке. Запускать изолированно, без production-токенов.
2. Развернуть тестовый экземпляр и отдельную YDB; проверить на вымышленных данных, включая два родителя у одного ребёнка и повторное поступление.
3. Создать контролируемый канал экспорта D1/Sheets/KV с пагинацией, checkpoint, checksum и шифрованием. Пробная миграция не отключает старый сайт.
4. Провести первичный импорт и несколько инкрементальных проходов. Протестировать passkeys, push, старые чаты, все отчёты, историю и выписки.
5. На согласованном cutover: поставить **короткий write-fence** на старой системе, дождаться завершения очередей, забрать дельту, сверить контрольные суммы, подготовить новый обработчик.
6. Одним переключением всех API на Timeweb/YDB открыть запись в новой системе. Проверить сценарии родителя, воспитателя, психолога на реальных устройствах.
7. Откат не означает простое возвращение на старую базу: сначала обеспечить экспорт/сохранение записей, созданных уже в YDB. Не удалять старые копии до утверждения плана восстановления и безопасного удаления.

## Что готово в этой ветке

- Черновая YQL-схема `services/ydb-next/sql/001_initial.sql`. Она требует проверки с реальной YDB **в тестовом контуре**, прежде чем применять к рабочим данным.
- Изолированный пакет Node.js `services/ydb-next` для отработки драйвера, транзакций и тестов без интеграции в действующий сервер.

- Полный API-паритет: `/lab/*`, `/push/*`, `/__session/apps-script`.
- Перенести алгоритмы Apps Script, включая исправление ручных переносов и защиту от изменения состава/владельца исходного отчёта.
- Реализовать отчётную вкладку воспитателей и редактор вариантов имён.
- Миграционные загрузчики/сверка без появления ПДн в логах и Actions.
- Настроить service account с минимумом полномочий, TLS, резервные копии, мониторинг RU/квот, ограничение доступа, план восстановления.
- Доказать функциональное соответствие на тестовой YDB, предусмотреть write-fence/один cutover.
- Sync Contacts: старый Apps Script trigger отключить *только* при финальном переключении, новое подключение к Google People API отсутствует.

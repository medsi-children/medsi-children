# Безопасное включение push на Timeweb

## До включения

- Выпустить проверенный коммит на `medsi-bot-main` и подтвердить его развёртывание в Timeweb App Platform 2.0.
- Оставить `MEDSI_NEXT_PUSH_DISPATCH_ENABLED=0` до окончания развёртывания. Отсутствующий флаг тоже означает «выключено».
- Не менять действующие VAPID-ключи. Проверить их наличие только в защищённом разделе переменных Timeweb, не переносить значения в чат, GitHub или логи.
- В выключенном режиме **новые сообщения и отчёты не создают push_outbox**. Старые строки очереди не удаляются, но не отправляются.

## Первое включение

1. Переключить только `MEDSI_NEXT_PUSH_DISPATCH_ENABLED` на `1`; перезапустить/развернуть приложение так, чтобы сервер принял новую настройку.
2. Первая активация создаёт в существующей PostgreSQL `migration_state` безопасную отметку `push_dispatch_safe_activation_v3`. Все созданные **до неё** push-события исключаются из доставки и постепенно переводятся в статус `expired`. При следующих обычных перезапусках отметка сохраняется.
3. Отправить одно **новое** тестовое сообщение после включения: родитель → воспитатель, затем воспитатель → родитель. Убедиться, что на каждом подписанном устройстве появляется ровно одно уведомление с реальным текстом.
4. Проверить новые отчёты и вложения по одному событию. По возможности повторить после перезапуска приложения.
5. Старые события никогда не отправляются заново. Возраст нового push ограничен **3 минутами**, обработка ограничена **12 событиями за 10 секунд**, ошибки повторяются не больше **5 попыток**. Старые события остаются в базе сообщений и отчётов, даже если их push истёк.

## Если уведомления снова идут потоком

- Немедленно установить `MEDSI_NEXT_PUSH_DISPATCH_ENABLED=0` и перезапустить приложение.
- Сами сообщения/отчёты в базе и медиа в S3 **не удалять**.
- Новое включение на уже использованной отметке не рассылает старый backlog, потому что проверяется дополнительно максимальный возраст события. Записи устаревшего push-outbox получают `expired`.
- Невозможно гарантировать доставку на конкретный телефон только по ответу Web Push-провайдера: проверить разрешение уведомлений в браузере/ОС и актуальность подписки. Не публиковать endpoint или auth/p256dh-ключи.

## Граница ответственности

Отправка push является дополнительным сигналом. Источник истины: сообщения и отчёты в PostgreSQL. Пропущенный или просроченный push не означает потери сообщения.

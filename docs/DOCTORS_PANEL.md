# Панель врачей Медси Бота

## Текущая архитектура: Google + Яндекс.Диск + локальная дата

- `DOCTORS_ENABLED=1` включает панель `/doctors` и API.
- `DOCTORS_GREENWOOD_SHEET_ID` задаёт таблицу «Стационар Гринвуд». Вкладка «5 этаж», заголовок во второй строке: C — ФИО, G — дата поступления, I — дата выписки. Сервер читает эти три колонки без записи в Google. В рабочем режиме колонка I задана явно в коде.
- Google определяет состав пациентов и исходные даты. Из столбца C исключаются служебные названия кабинетов, ординаторской и аналогичных помещений, заголовки, пустые строки и записи без букв. Отсутствие даты или неполное имя само по себе не исключает пациента. Открытая панель проверяет список каждые 30 секунд; серверный кеш — 25 секунд. При временном отказе Google допускается отображение последнего успешно полученного списка, но сохранение даты требует свежего реестра. Без настроенного реестра доступен прежний список зарегистрированных родителей без возможности редактировать даты.
- Ручное изменение даты выписки врача сохраняется в PostgreSQL со статусом local. Оно имеет приоритет над последующими изменениями столбца I для той же строки и даты поступления. Дата поступления берётся из Google. Новое пребывание не наследует дату предыдущего.
- Из старой таблицы doctor_discharge_changes сохраняются ранее явно установленные врачом даты при совпадении идентификатора и даты поступления; снимки, полученные из Excel, игнорируются. Старые ожидающие операции не отправляются на Диск. Строки без корректного поступления видны, но редактирование дат отключено.
- Яндекс.Диск снова читается каждые пять минут при наличии DOCTORS_DISK_ROOT и DOCTORS_DISK_TOKEN. По умолчанию клиент создаётся без права загрузки. Для нового механизма записи требуется отдельное включение, старые флаги сами по себе ничего не запускают. Google определяет актуальные строки и дату поступления. Справочник имён, перестановка имени и фамилии, суффиксы возраста, месяца и даты и единичная опечатка в названии папки помогают найти кандидатов. ФИО внутри документа и дата поступления должны однозначно подтвердить пациента. Итоговый план с явной выпиской предпочтительнее обычного, затем предварительного. Между планами одной категории выбирается файл с более поздним временем создания на Диске, затем учитываются время изменения и дата в имени. Если по этим признакам нельзя выбрать между разными датами выписки, используется дата из реестра, если она есть. Одиночная дата в C2 — только поступление, обратный диапазон или нулевой день недействительны. При отсутствии проверенной выписки значение Google отображается с отметкой ориентировочной даты; ручная дата главнее всех. До включения нового режима записи файлы не редактируются, новые копии S3 не создаются. Исторические данные и секреты не удаляются.
- Диагностика после входа: `/doctors/api/diagnostics`. Режим google-disk-read-local; diskEnabled и вложенный disk показывают состояние чтения планов, агрегированные статусы и причины. Google counters показывают числа полученных строк, дат поступления и выписки, отметку последнего чтения и stale. Эти числа относятся к Google, а не к ручным правкам. Без персональных данных.

## Список пациентов

Врач может убрать карточку из активного списка и вернуть её через «Убранные». Решение сохраняется в PostgreSQL для текущей строки и даты поступления. Оно действует для всех врачей. При новом поступлении карточка появляется снова. Google и файлы планов при этом не меняются.

## Доступ и контакты

- Вход использует `DOCTORS_LOGIN` и `DOCTORS_PASSWORD` либо прежние `NEXT_TUTOR_LOGIN` / `NEXT_TUTOR_PASSWORD`. Отдельная врачебная cookie.
- `DOCTORS_EXCLUDED_PHONES` фильтрует тестовые телефоны. Телефонная книга берётся из PostgreSQL.
- Контакты на карточке пациента требуют отдельно проверенной связи через `DOCTORS_VERIFIED_CONTACT_LINKS`: JSON-массив пар непрозрачных идентификаторов строки реестра и ребёнка в боте. По имени контакты автоматически не назначаются. Связь не переносится на другую госпитализацию.
- Доступ к медицинскому реестру должен быть согласован ответственным за конфиденциальность. Текущий gviz-запрос не использует OAuth. Не открывать таблицу публично без разрешения и не сохранять её ID, реальные записи или секреты в Git и логах.

## Проверка

`npm run verify` и `npm run verify:postgres-next`. Тесты doctor panel проверяют проекцию C/G/I, неизменность врачебной даты при обновлении Google, конкурентное редактирование, исчезновение строки и новую госпитализацию. Интеграционные тесты запускаются на изолированной PostgreSQL с синтетическими данными. Исторические тесты записи Disk остаются, но старый обработчик не подключается в runtime. Новые тесты проверяют чтение, дубликаты и ошибочные даты.

## Рабочая запись после проверки чтения

Новый механизм не воспроизводит прежнюю очередь. Только новая явная правка врача создаёт задание на запись в проверенные XLSX текущей госпитализации. Список путей и контрольных сумм фиксируется при сохранении. Допускаются обычные, итоговые и предварительные планы в подходящих папках, а также планы в корне с совпадающим словом имени/фамилии; название — только подсказка поиска, внутри обязательно совпадение ФИО и поступления. Неопознанные, некорректные и старые планы не меняются. Если версия или набор проверенных документов изменились, требуется повторное сохранение даты после проверки. Если планы ещё не обнаружены, дата остаётся в боте и задание требует повторного сохранения. Одиночное числовое значение без времени допускает замену на текстовый диапазон в той же ячейке, без изменения остальных ячеек.

Включение только после проверки чтения и синтетического теста записи на изолированном стенде:
- DOCTORS_DISK_SMART_WRITE_ENABLED=1
- DOCTORS_DISK_CONCURRENT_EDIT_ACK=1 (подтверждает, что нет одновременного ручного редактирования файлов при загрузке; у API Яндекса нет атомарной проверки версии при замене)
- DOCTORS_DISK_WRITE_EPOCH — новый уникальный идентификатор поколения из 12–128 допустимых символов.
- Настроенный закрытый S3 и существующие OAuth, реестр и корень.

Операции из другого поколения не исполняются. Временные оригиналы и манифесты в S3 создаются до загрузки, проверяются хешем и автоматически удаляются после подтверждения всех документов и фиксации статуса synced. При ошибке сохраняются для восстановления; очистка повторяется в следующих циклах. Не удаляются старые объекты и исторические версии. Google остаётся только на чтение. 

### Расхождение поступления на сутки
Если совпадает буквальное имя и фамилия, запись единственна в актуальном реестре, а поступление в плане отличается ровно на один календарный день, явно указанную выписку можно использовать для отображения. Среди таких планов действует тот же приоритет типа и свежести. Если выбрать план нельзя, показана дата из реестра, если она есть. Точное совпадение госпитализации имеет приоритет. Никакие документы с такой разницей автоматически не перезаписываются, операция записи блокируется до проверки. Диагностика содержит отдельные счётчики admissionOffOneDay и withCandidateDischarge без персональных данных.

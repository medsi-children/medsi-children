# Панель врачей Медси Бота

## Timeweb

- `DOCTORS_ENABLED=1` включает `/doctors`. Удаление флага отключает страницу, API и фоновую синхронизацию. Записи в PostgreSQL сохраняются.
- Вход по умолчанию использует `NEXT_TUTOR_LOGIN` и `NEXT_TUTOR_PASSWORD`. Для смены учётных данных врачей задайте одновременно `DOCTORS_LOGIN` и `DOCTORS_PASSWORD`. Врачебная сессия использует собственную cookie.
- `DOCTORS_EXCLUDED_PHONES` принимает список тестовых телефонов через запятую. Этот фильтр применяется при чтении телефонной книги бота.
- `DOCTORS_GREENWOOD_SHEET_ID` включает чтение реестра «Стационар Гринвуд». Нужен ID между `/d/` и `/edit` и доступ на чтение по ссылке. Бот делает только анонимный запрос к вкладке «5 этаж» за ФИО и датой поступления. Дата из таблицы помогает различать повторные госпитализации и не отображается как клиническая дата на карточке. При временном отказе Google панель показывает последний полученный список, если он есть в памяти процесса. Изменения при недоступном реестре отклоняются.
- Без `DOCTORS_GREENWOOD_SHEET_ID` проверять интерфейс можно со списком из PostgreSQL. Телефоны и имена родителей доступны в карточке «Телефоны». В режиме Google контакты на карточках пациентов требуют подтверждённого соответствия между строкой и профилем. В текущей вкладке общего идентификатора нет.
- `DOCTORS_DISK_ROOT` задаёт путь к папке пациентов, например `disk:/Документы/Пациенты`. `DOCTORS_DISK_TOKEN` берётся из секретов Timeweb. `DOCTORS_DISK_INTERVAL_MS` по умолчанию составляет 300000 мс.
- `DOCTORS_DISK_TEST_WRITE=1` вместе с `DOCTORS_DISK_WRITE_TEST_ROOT`, совпадающим с `DOCTORS_DISK_ROOT`, разрешают запись в явно заданную тестовую папку с копиями. Перед включением настройте закрытый S3 и срок хранения объектов с префиксом `doctor-plan-backups/`. В рабочей среде с оригиналами оставьте тестовые параметры пустыми.

## Подключение Яндекс OAuth

1. Создайте OAuth-приложение в [Яндекс OAuth](https://oauth.yandex.ru/). Выберите право чтения Яндекс.Диска (`cloud_api:disk.read`). Для отдельной учётной записи с тестовыми копиями и проверкой записи добавьте право `cloud_api:disk.write`.
2. Авторизуйтесь как владелец нужных папок, пройдите согласование и получите токен через [официальный OAuth-процесс](https://yandex.com/dev/disk/rest/).
3. Запишите токен в переменную `DOCTORS_DISK_TOKEN` в настройках приложения Timeweb. Укажите путь, заданный в `DOCTORS_DISK_ROOT`. Пароль от Яндекс-аккаунта для бота не требуется.

## Изменение выписки

Правка врача сначала фиксируется в PostgreSQL. Синхронизатор проверяет принадлежность документов, выбирает планы текущего пребывания, проверяет даты во всех файлах и сохраняет копии перед загрузкой. После каждой загрузки скачивает файл и сверяет хеш. Если процесс прерывается после загрузки части файлов, повторная проверка пропускает планы с уже установленной датой. Обнаруженное изменение выписки, отличное от ожидаемого значения, останавливает запись и отображается в карточке.

Яндекс.Диск не предоставляет проверенную атомарную операцию сравнения версии при перезаписи через ссылку загрузки. Между заключительной проверкой и загрузкой остаётся окно для внешней правки. Запись с текущими настройками предназначена для тестовой папки.

## Проверка

`npm run verify` и `npm run verify:postgres-next` проверяют приложение. Для дополнительной проверки очереди на локальном чистом PostgreSQL передайте его порт в `MEDSI_DOCTORS_TEST_PG_PORT` и запустите `node --test services/postgres-next/app-test/doctors-panel.test.mjs`. Тест пользуется синтетическими документами и имитирует Яндекс.Диск и S3.
